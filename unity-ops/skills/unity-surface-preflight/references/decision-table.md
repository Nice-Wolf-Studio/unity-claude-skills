# Batch-vs-live decision table

One table, evaluated top to bottom, **first match wins**. `unity-ops:unity-surface-preflight` applies it; this is the shipped copy (DESIGN.md §4, revision 5, amended by the Increment 0 Deltas — see the note at the bottom).

Row 3a (`STATUS_NO_INSTANCES`) is evaluated **before** the `AMBIGUOUS_EDITOR` row, which otherwise swallows the flagship no-Editor case. Row 3a routes to **row 3b**, not straight to row 5: row 5's own predicate requires "no headless answer (row 3b)", and IA:162-164 says in as many words that a batch-mode Editor *does* serve commands while producing exactly the `STATUS_NO_INSTANCES` that row 3a matches. Every Safe-Mode line filters instead of passing a project argument — `pipeline list` has no such flag.

| # | Observable predicate (evaluate in order) | Surface | Why |
|---|---|---|---|
| 0 | `command -v unity` fails, or the `claude-code` row in `unity skill install --list` is **not** installed (anchored match) | **STOP** — give the install command, do nothing else | Dependency contract (§5) |
| 1 | `unity pipeline list --format json` → `data.summary.instancesInSafeMode > 0`, **and** the per-project filter over `data.instances[]` matches this project: `jq --arg p "$PWD" '.data.instances[] \| select(.projectPath == $p)'` | **NEITHER** — fix compile errors in `.cs` source, then restart | In Safe Mode the Pipeline package does not load, so `status`/`command`/`list` cannot connect at all; editing source here is correct, not a fallback (IA:348-357). **`pipeline list` is machine-wide — there is no `--project-path`** (`unity pipeline list --help` lists no options of its own beyond `-h, --help`; a Global Options block prints after it and is the CLI's shared set, not this subcommand's; passing a project flag → `error: unknown option '--project-path'`). The field on `data.instances[]` carrying the project path was **observed in Increment 0 as `projectPath`** (Delta D2, `tests/pipeline-list-shape.md`) — an absolute, non-trailing-slash string that compared byte-equal to `$PWD` from the project root, so the R2-10 ASK degradation does **not** fire and this row resolves per project. Two limits on that: the equality was observed from the project root only, so from a subdirectory or a symlinked root you normalise both sides or you do not fire; and a **zero** machine-wide counter is a safe negative for every project while a non-zero one is not a positive for any, because the Safe-Mode-**positive** shape of `data.instances[].safeMode` has never once been seen. Delta D3 filed that field as JSON `null`; on 2026-09-14 it came back as an object reading `{"detected": false, "confidence": "high"}` (Delta D14, issue #31), so the earlier note is stale but the rule it protected is not — a field that has only ever been watched saying "no" teaches you nothing about how it says "yes", so never test `.safeMode.detected` for truthiness. |
| 2 | The deliverable is a **verdict or artifact you will later quote as evidence** — a build, a test result, a coverage report, a CI-reproducible check | **BATCH** (`build`/`test`), even with a live Editor reachable | Exit-code contract, report files, provenance manifest; a live edit leaves no replayable record (SK:129-139; BRT:331) |
| **3a** | **`unity status --format json` → `errors[0].code == "STATUS_NO_INSTANCES"` (equivalently `success:false` with `data.count:0` and `data.instances:[]`)** | **GO TO ROW 3b**, and if 3b errors with `COMMAND_FAILED` too, on to row 5 — this is *no candidates*, not *too many*. Do **not** treat it as an ambiguity to resolve, and do **not** conclude "closed", and do **not** skip the headless check. | **Observed by live probe on this machine**: exit 6 with `STATUS_NO_INSTANCES`; IA:337 documents the code token only, not `data.count:0`/`data.instances:[]` **[R4-M5]**. Without this row, row 4's exit-6 test captures the flagship no-Editor case and routes it to LIVE-with-`--project-path` against candidates that do not exist. **Arbitration against `pipeline list` (issue #30):** a `runningInstances` counter or an `isRunning: true` flag in that payload does **not** cancel this row and does **not** hold you back from row 5. This row keys on `unity status`, on nothing else; `isRunning` was watched reading `true` on 2026-09-14 for a project whose Editor was shut and whose process table held no Unity binary at all, `pipelineServer.isReachable: false` beside it in the very same object. Reachability is `isReachable`. |
| 3b | A **headless/batch-launched** Editor is expected for this project: `unity list --project-path <project>` (or `unity command`) answers **with its tool catalog** — 151 entries when Increment 0 watched it — even though `unity status` did not list it | **LIVE** via `unity command … --project-path <project>` | A batch-mode Editor serves commands but is **not listed by `unity status`** — its lockfile heartbeat differs from a GUI Editor's. Confirm with `unity list --project-path`, not `status` (IA:162-164). **This probe has exactly two answers and neither of them is "empty"** (issue #27): a catalog, or `{"success":false,"data":null,"errors":[{"code":"COMMAND_FAILED","message":"No Pipeline instance found for project: …"}]}` at exit 6, which is the negative that sends you on to row 5. Anything you were tempted to call an empty list is one of those two, misread. For a warm Editor opened by `unity open`, `unity status` **does** gate readiness (IA:166-168). If a probe here **hangs** rather than answering, `unity command editor_status` is the first thing to run, not the last: it answers instantly even while the main thread is blocked and reports `blocked_by_dialog` with the dialog's title, message and buttons (UP:162-165, Delta D8) — a blocked Editor is a live Editor, and a hang is never evidence of absence. |
| 3 | `unity status --format json` → `data.instances[]` contains this project at state `ready`, exactly one candidate | **LIVE** (`unity command …`) | 200–600 ms round trip, no recompile, no domain reload; the Editor applies changes to the *actual active scene* (IA:133-136). Before driving a warm Editor from a headless session, assert the LIVE precondition `unity command set_autotick --enable true` — UP:26-28 calls it required before headless work because Unity throttles or stalls update and compile when it is not the active app (Delta D8); it is itself a mutating command and carries the same single-project sanction `unity open` has. |
| 4 | `unity status` shows ≥2 instances, **or** a command returned exit 6 with **`errors[0].code == "AMBIGUOUS_EDITOR"` and non-empty `data.candidates`** | **LIVE, with an explicit `--project-path`** resolved from `data.candidates` | Shared resolver: `--runtime` > `--project-path` > deepest cwd-containing project — the target otherwise follows the shell's cwd (IA:11-15,21,33). **Both conditions are required**: exit 6 alone is not enough, and neither is `AMBIGUOUS_EDITOR` with an empty candidate list. |
| 5 | No instances anywhere (row 3a), no headless answer (row 3b), Safe Mode ruled out (row 1). **Those three are the whole predicate — there is no fourth.** Whether your own shell is walled off from the rest of the machine is not something you can probe from inside it, so it is never a condition you must first satisfy; it is the reason the question exists | **ASK THE HUMAN** — "my sandbox may be hiding a running Editor; is one open?" Do not conclude, do not substitute | A walled-off shell reproduces "no instances" against a running Editor, and from in here you cannot tell which of the two you are looking at — that unknowability is precisely why you hand the question over instead of resolving it yourself. **This caveat is absent from the skill you have loaded** (GitHub-only) — it will not warn you. Never suggest disabling the sandbox. The three conjuncts held in all four T2.4 result runs and none of them asked; if you are here, ask. |
| 6 | Human confirms no Editor, and the work is **one** editor-side action | **BATCH one-shot**: `unity run --command <name> -- <args> --format ndjson` | Boots a fresh batch Editor per invocation; ndjson because the Editor log interleaves with the result on stdout. Note `run` is the **only** one of the three documented to reuse a running Editor (BRT:43). |
| 7 | Human confirms no Editor, and the work is **iterative** (>3 editor actions expected) | **BATCH persistent-headless** (then verify with `unity list --project-path`, per row 3b), or ask the user to `unity open` and re-run this table | Avoids N cold Editor boots. `unity open` is authorized by an agent **only** for `~/Dev/Unity/ai_test` (§4B) |
| 8 | The action needs a UPM package added or removed | **NEITHER by default** — route to Unity's `unity-package-management` skill. A CLI path exists and is documented, but it is **not yours to take unasked**: stop and ask before any `package_add`. | Revision 5's "out of CLI scope entirely" is **falsified** (Delta D8): `unity command package_add --identifier com.unity.project-auditor-rules --confirm true` (UP:154-155) is a documented, loaded, CLI-reachable UPM mutation. Its scope is unstated upstream — it may be Project-Auditor-rules-specific or general — so the predicate does not tell you it will work for your package. And `--confirm true` is a `--yes`-shaped auto-confirm on a mutating command, the exact class G6 forbids and `unity-ops:unity-destructive-gate` covers. Because the table is first-match-wins and this row sits below the LIVE rows, a mis-route here is silent. |
| 9 | None of the above resolved | **ASK** | An unresolved surface is a question, never a default |

**Never**, at any row: hand-edit `.unity` / `.prefab` / `.asset` YAML while a live Editor is reachable; silently substitute a fresh headless Editor for a live connection; or conclude "no Editor" from `unity status` alone. If a disclosed YAML fallback is genuinely the only path, say the sentence out loud: *"no live Editor detected (Safe Mode ruled out, headless ruled out with `unity list --project-path`, sandbox ruled out with the user) — editing the file directly."* Note this is **longer** than the installed skill's own sentence at SK:184, deliberately: SK:184 authorizes the fallback on "no reachable Editor" with no ruling-out requirement at all.
